# Studio Mistral : refus HTTP 422 confirmé, cause exacte encore inconnue

Run : https://github.com/benoitlub/poulpe-fiction/actions/runs/42577164619
Le cycle du 9 novembre à 07:07 UTC s’arrête pour prohibited-online avec
`MISTRAL_IMAGE_UPSTREAM_FAILED`, `httpStatus:422`, après fusion de Publisher #200.
Aucun succès image n’est confirmé par ce run. Il ne démontre pas un quota 429.

Le code supprimait entièrement le corps d’erreur Mistral. Il conservait le
statut mais pas le message de validation ni le champ rejeté. Les schémas publics
ConversationRequest/CompletionArgs consultés le 9 novembre acceptent les champs
envoyés, y compris `model`, `tools` et `completion_args.tool_choice:any`. Cela
ne prouve pas que le compte ou le service réel accepte cette combinaison ; aucun
champ précis ne peut être accusé à partir du journal disponible.

Le correctif distingue désormais 400/422 avec `MISTRAL_IMAGE_REQUEST_INVALID`,
conserve l’identifiant de requête et les détails de validation utiles, masque
la clé et le texte envoyé si le fournisseur les répète, et exclut les structures
`input` et `ctx`. Les autres erreurs ne réexposent pas leur corps fournisseur.
L’ancien endpoint média s’arrête aussi sur les refus de requête, d’accès ou de
facturation : pas de second appel identique ni de bascule vers un autre moteur.

Les anciens rapports ne sont ni effacés ni relancés automatiquement. La forme
de la requête n’est pas modifiée sur la seule hypothèse d’un paramètre invalide.

Validation : 150 tests Worker réussis, un test Postgres ignoré sans base de test,
TypeScript Worker et `git diff --check` réussis. Les refus 400/422 et les messages
de validation sont simulés ; les assertions contrôlent la non-divulgation des
valeurs de test et l’absence de seconde tentative. Aucune génération Mistral,
publication, fusion ou déploiement n’est exécuté.

**Blocage restant :** pour corriger la cause exacte et confirmer la production,
il faut une réponse réelle avec ces diagnostics ou la validation du fournisseur.
Une nouvelle tentative peut consommer des crédits et nécessite une autorisation
distincte. Cette PR améliore le diagnostic et l’arrêt sûr ; elle ne constitue
pas une preuve de déblocage de la génération.
